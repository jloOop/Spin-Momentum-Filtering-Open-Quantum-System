# Reproducing the selected results

The normal workflow is CPU-only and reads files inside this checkout. It does not import a production solver, require CuPy, query the research archive, or modify bundled reference arrays.

## Environment and commands

The tested analysis environment is Python 3.13.15, NumPy 2.5.4 and Matplotlib 3.11.2. These are the environment used for this release's reductions, not a reconstruction of historical GPU production environments.

~~~bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python Loaders/reproduce.py --group canonical --output build/canonical
python Loaders/reproduce.py --group extensions --output build/extensions
python Loaders/reproduce.py --group finite-rate --output build/finite-rate
python Loaders/reproduce.py --group foundations --output build/foundations
python Loaders/verify_release.py
~~~

Run from the repository root. Outputs must be inside ignored build/ directories. The four commands regenerate figures and numerical CSV/JSON summaries; the verifier checks hashes, archive readability, safe array schemas, role coverage, privacy patterns and primary documentation links. A failed check exits nonzero. Passing these checks is not a new scientific acceptance decision.

## Finite-rate views and outputs

~~~bash
python Loaders/reproduce.py --group finite-rate --output build/finite-rate
~~~

This single command regenerates both views from the already bundled histories. `finite_rate.png`, `finite_rate_cumulative.png` and `finite_rate_normalized.png` use the extended saved support; `finite_rate_poster.png` uses the verified historical cutoffs 5.65, 8.3 and 3.6. The [results page](data/finite_rate/README.md) displays the principal products and distinguishes historical from extended statistics. No archive access or optional poster mode is needed.

`matched_horizons.csv`, `integrated_rate_doubling.csv` and `response_mass_windows.csv` use native probability differences; the older A127 outputs remain available. `poster_regression.json` records the comparison to bundled historical reductions, including the unrounded 5.65 doubling calculation. [Prefix verification](data/finite_rate/poster_provenance/prefix_verification.json) establishes exact identity of all 27 arrays per historical branch, including time grids and paired zeros; this was checked against the local source snapshots when preparing the update. The portable command checks the bundled numerical reductions, and the release verifier checks distributed hashes. Neither reruns the source archive scan nor treats inherited prefixes as independent runs.

## Numerical conventions

Native roof-bin probabilities determine click mass and click-time moments. State-node times, bin midpoints, detector step, insertion spacing and response-panel width have distinct roles. No dense density is inferred by differentiating sparse survival. Independent stored roof and survival channels are never forced to close by rewriting them.

Each positive Task09 history carries its own paired zero. Standalone zero is compared only on its actual support. Current endpoints are checked from arrays and metadata: pi1600 10, pi3200 6, pi800 3.825, standalone zero 3.6. Common-support rate comparisons end at 6 or 3.825 as appropriate; paired-zero checks against standalone zero stop at 3.6. No missing support is interpolated and no inherited prefix becomes a new independent trajectory.

Representation loss, event omission, overflow diagnostics and accounting residuals remain separate. The applicable active policy is preserved alongside older policy fields. Restricted means, detection-conditioned means and numerical loss contributions are reported with their definitions; near-linear doubling is only descriptive.

## Archived code, aliases and omissions

Solvers/ contains accessible historical generating families and selected small configuration/helper closures. Distinct pi3200 parent/recovery and pi800 base/KL2 implementations remain separate. Loaders/archive/ preserves historical reading and analysis sources. These are inspectable provenance, not additional advertised runnable entry points; historical internal paths and source manifests refer to original bytes.

The new wrappers port the bounded reduction logic, with source attribution in their module headers and [release manifest](data/provenance/release_manifest.csv). [aliases.csv](data/provenance/aliases.csv) resolves shared pi1600 history/config and U2-I reference destinations. Equal bytes justify sharing; similar names do not. Privacy-sanitized documents and ZIP text members have separate original/distributed hashes. Numerical members remain byte-identical. Historical source hashes inside original reports are not silently rewritten to match sanitized copies.

SciPy is needed by some archived bath loaders but is not required by the advertised commands. ReportLab is optional for archived PDF-report code; PDF generation is not part of the tested quick start. Full A127 spectral auditing, original Task06 raw-array re-audit, production simulations, historical state restarts and native reconstruction of all extension figures were not run and are not advertised. See [PROJECT_SCOPE.md](PROJECT_SCOPE.md) and the short [release checks](data/provenance/release_checks.json).
